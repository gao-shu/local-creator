# 开源 GTM · 横切审核标准（Rubric）

所有 OA/OB/OC 节点的「审核标准」必须能映射到下列级别之一。验收时在阶段档「验收记录」写明级别与证据路径。

## 证据级别

| 级别 | 含义 | 合格证据示例 |
|------|------|----------------|
| **L0 文档** | 仅文档/决策 | 文件存在；关键段落非空；链接可点 |
| **L1 静态** | 仓库静态检查 | `rg` 零命中或命中已解释；`LICENSE` 存在；无密钥模式 |
| **L2 构建** | 可编译 | `npm run compile` exit 0 |
| **L3 自动测** | 自动化 | 约定的 `npm run test:e2e:smoke` 或节点指定脚本 exit 0 |
| **L4 手测** | 真人路径 | 步骤列表 + 截图目录 `docs/evidence/OAx/`（或网盘链接写在验收记录） |
| **L5 分发** | 安装包/更新 | Setup 可装；`SHA256` 文件；更新检查行为符合预期 |

## 节点状态机

```text
未开始 → 实现中 → AI自检通过 → 人审核 → 通过 | 打回
```

- **AI自检通过**：AI 按节点「实现方式」做完，并跑完该节点「审核标准」中标注为 AI 可执行的项，在验收记录填「AI：通过/失败 + 命令输出摘要」。  
- **人审核**：人勾选「人：通过」；涉及品牌、法律、对外文案、公开仓库的项**必须人审**。  
- **打回**：写明缺陷与重做范围；不得带着失败项进入下一节点。

## 通用否决项（一票否决）

出现任一项，当前节点**不得**标通过：

1. 提交或文档中出现疑似 API Key、内网地址、客户项目数据。  
2. 用「隐藏 UI」冒充「已删除」公司耦合（与 L2 原则冲突）。  
3. 开源核无法在无商业模块下 `compile` + 启动。  
4. 审核标准写成主观句且无可复现步骤（如仅写「体验更好」）。  
5. 证据与本仓库版本/commit 对不上（验收记录须写 commit 短 SHA）。

## 文案与品牌审核（人）

- 对外 README/官网/安装包名：**无**公司商标、无「好的」「Haode」等禁用名。  
- 免责声明含：第三方 API 费用与 ToS 由用户自负。  
- 不承诺「完全离线大模型」或未实现的能力。

## 安全最小集（OA 起每次发版前抽查）

```powershell
# 在仓库根；命中需人工解释或清除
rg -n -i "sk-[a-zA-Z0-9]{10,}|api[_-]?key\s*[:=]\s*['\"][^'\"]{8,}" --glob "!node_modules/**" --glob "!package-lock.json"
rg -n -i "haodou|weishi_api|好的漫创" --glob "!node_modules/**" --glob "!docs/**"
```

> `docs/**` 中讨论性提及公司名可保留在删除清单历史中；**产品代码与 README** 不得宣传公司产品。
