# OC · Phase C（60～90 天+）可商业化挂钩

> **依赖**：OB 阶段验收通过。  
> **横切**：[oss-gtm-review-rubric.md](../oss-gtm-review-rubric.md) · 决策 D2/D6  
> **指挥**：`执行 OC` / `执行 OC1` … `OC 阶段验收`  
> **原则**：开源核永不依赖商业壳才能完成「剧本→分镜→导出」主路径。

## 阶段目标

1. **商业壳边界**可执行（另仓或私有包），开源仓可独立构建。  
2. **第一商业切口**（D6）最小闭环（哪怕只有人工下单）。  
3. **薄扩展面**让社区可贡献模板/Skills 清单。  
4. **信任基建**：架构文档、CI 徽章、安全说明。

## 阶段完成定义（DoD）

- [ ] OC1～OC4 通过  
- [ ] OC5 按 D6 通过或书面延期  
- [ ] 人确认「开源信任未被商业话术破坏」

## OC1 · 商业模块加载边界（工程）

### 目标

实现或书面规定：公开源码树**不含**必须闭源才能编译的符号；商业功能通过另仓包/运行时插件注入。

### 实现方式方案

1. 在开源仓定义稳定接口（例如 `CommerceHooks` 空实现 / no-op）。  
2. 另仓（或 `private/` 不发布）实现真正逻辑；文档写清构建矩阵：  
   - `开源-only` CI  
   - `开源+商业` 内部 CI  
3. 验收：删除商业包后 `npm run compile` 与主路径手测仍过。

### 审核标准

| # | 标准 | 级别 | 执行方 |
|---|------|------|--------|
| C1.1 | 边界文档与 D2 一致 | L0 | 人 |
| C1.2 | 开源-only `compile` 通过 | L2 | AI |
| C1.3 | 开源-only 主路径手测通过（无商业入口或入口提示升级） | L4 | 人 |
| C1.4 | 公开树无商业密钥与未发布私有 URL 硬编码 | L1 | AI |

## OC2 · 薄扩展面（Provider / Skills / 模板清单）

### 目标

社区可 PR「提示词包 / Skill 描述 / 推荐 Provider 元数据」，无需改核心也能登记。

### 实现方式方案

1. 冻结一份 JSON Schema：`skills-pack`、`prompt-pack`、`provider-catalog`（仅元数据）。  
2. 仓库 `community/` 或 docs 说明提交流程。  
3. 应用可「从文件导入」；暂不做在线市场也合格。

## OC3 · 架构文档 + 安全模型 + CI

### 目标

外部贡献者与企业评估方能理解分层与威胁边界；主分支有最小 CI。

### 实现方式方案

1. 恢复或新写 `docs/ARCHITECTURE.md`：主进程/渲染/IPC、数据根、模型调用。  
2. `docs/SECURITY-MODEL.md`（或扩写 SECURITY.md）：Key 存储位置、无电话回家、更新源信任。  
3. CI：`lint` + `compile` + `test:e2e:smoke`（可按资源裁剪，但须在文档写明）。  
4. README 徽章指向 CI。

### 审核标准

| # | 标准 | 级别 | 执行方 |
|---|------|------|--------|
| C3.1 | ARCHITECTURE 存在且与代码目录大致一致 | L0 | 人 |
| C3.2 | 安全说明含 Key 与更新源 | L0 | 人 |
| C3.3 | CI 在默认分支可运行且最近一次绿（或跳过原因书面） | L3 | AI/人 |

## OC4 · 平台覆盖（Mac 评估）

### 目标

书面结论：是否正式支持 Mac；若支持则出包与最小手测清单。

### 实现方式方案

1. 评估 electron-builder Mac 签名/公证成本。  
2. 二选一：  
   - **支持**：CI 或手工出 dmg + 手测开向导  
   - **暂不支持**：README 明确 Windows-first，Mac 为 best-effort  
3. Linux 默认后置。

### 审核标准

| # | 标准 | 级别 | 执行方 |
|---|------|------|--------|
| C4.1 | README 平台支持声明与事实一致 | L0 | 人 |
| C4.2 | 若宣称支持 Mac：存在可下载包 + 启动手测 | L5/L4 | 人 |

## OC5 · 第一商业切口最小闭环

### 目标

按 D6 跑通「有人愿意付费的路径」——允许人工履约，但入口与交付物清晰。

### 实现方式方案

| D6 | 最小闭环 |
|----|----------|
| 精品模板订阅 | 官网下单/联系 → 交付 pack 文件 → 应用导入成功 |
| 优先支持服务 | 价目与响应时效说明 → 工单邮箱/企微 → 一次付费记录 |
| 可选云同步 | 另仓服务 + 开源客户端开关默认关；隐私说明；一人双设备验证 |
| OC 再定 | 本节点只输出选型实验报告，不强制上线 |

禁止：开源核主路径锁定付费；强制账号才能导出。

### 审核标准

| # | 标准 | 级别 | 执行方 |
|---|------|------|--------|
| C5.1 | 与 D6 一致的方案说明文档 | L0 | 人 |
| C5.2 | 开源-only 主路径仍免费可用 | L4 | 人 |
| C5.3 | 至少 1 次真实或模拟成交走通（模拟须人认可） | L4 | 人 |
| C5.4 | 对外文案无误导「开源版不能剪映导出」等 | L0 | 人 |
