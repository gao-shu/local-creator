## OA1 · 许可证与开源/商业边界

### 目标

法律上可回答：别人能怎么用开源核；商业壳如何与开源核隔离。

### 实现方式方案

1. 按 D1 在仓库根添加 `LICENSE`（全文官方文本）。  
2. 新增 `docs/appendix-commercial-boundary.md`（或恢复商业附录）：写明  
   - 开源核范围（目录/能力列表）  
   - 商业壳加载方式（另仓 / 私有包）  
   - 贡献者许可（CLA 可选：Apache 下可先写「贡献即按本仓许可证」）  
3. `README.md` 顶部增加 License 徽章与「商业咨询」占位链接（可为 issue 模板链接）。  
4. `package.json` 的 `"license"` 字段与 `LICENSE` 一致。

## OA5 · 首次运行向导（TTFV）

### 目标

新数据目录用户启动后，**强制或强引导**完成：存储位置 → 至少一个可用模型（LLM 或图片）→ 测试连接 → 进入首页或示例入口；减少「空白设置不知所措」。

### 实现方式方案

1. 梳理现有：存储初始化、设置页、登录模式（已强制本地）。  
2. 新增「首次运行」状态机（建议：`localStorage`/settings 标志 `onboarding.completed`）：  
   - Step1 选择/确认数据目录  
   - Step2 添加模型（可只要求图片或 LLM 其一，按产品选择写死）  
   - Step3 「测试」成功或用户显式跳过（跳过须二次确认）  
   - Step4 结束 → 仪表盘；可选「打开示例」（示例项目可在 OB1 完善，本节点可先占位按钮 disabled + 说明）  
3. 已完成 onboarding 的老用户不打断。  
4. 补充最小单测或 e2e：`onboarding` 标志为 false 时出现向导（若时间紧，L4 手测可过，但须在记录注明「无自动测」）。

### 目标

### 实现方式方案

1. `npm run build`（或项目约定 `build:win`）产出 Setup。  
2. 生成 `SHA256SUMS` 或单文件 `.sha256`。  
3. 若 D/环境允许：配置 `VITE_UPDATE_PUBLISH_URL`，上传 `latest.yml` + 包，验证「检查更新」；若暂无公网，则文档写明「未配置时检查更新的提示文案」并手测该提示。
